Nimbus Diagram Design System

Tokens, spacing and components for the Mermaid, DBML and diagram renderers in Nimbus Markdown. Derived from content/mermaid.js, content/index.css and the renderers in content/*.js. Everything below is drawn with the live tokens, so use the toggle to check both themes.

Principles

PrincipleMeaning
Quiet paper, one accentNeutral surfaces and ink; a single accent marks focus, selection and the active step.
One gridAll geometry snaps to a 4px grid (grid(v) = ceil(v/4)*4); spacing comes from a small fixed scale.
Themes switch without recompilingColors reach the SVG through --ondine-* custom properties, so light/dark is a property swap only.
Mono for labels, sans for contentEyebrows, chips and counters use Geist Mono; node text uses Geist.

Rules

  • New work picks a step from the scale. Every size is a multiple of 4. Larger layout constants (DBML node gap 56, journey column 200) are multiples of the base and sit above the scale.
  • Gaps inside a component are smaller than gaps between components.
  • Text widths and box sizes round up with grid(), never down, so content never clips.

Guidelines

Do

  • Use tokens, never raw hex, in new renderers.
  • Use one accent per diagram for the thing that matters.
  • Snap sizes to the 4px grid with grid().
  • Check every change in both themes.
  • Keep mono text to labels, chips and numbers.

Don't

  • Use accent as the fill of large areas.
  • Add shadows to nodes; elevation is for floating controls only.
  • Mix radii inside one component.
  • Use series colors to mean status; use danger for errors.
  • Animate outside fullscreen, or ignore reduced-motion preferences.

Accessibility

  • Body text and node text use ink or muted on paper/node; small accent text uses accent-text.
  • Icon-only buttons carry an accessible name.
  • Selection and focus are shown by color, stroke width and dimming of the rest, so no state relies on color alone.
